# Product ID

## Definition
Product ID is a unique alphanumeric identifier that represents a specific sequencing product output - the raw data generated from a particular biological sample as it was physically sequenced in a defined location on a sequencing instrument. It identifies not the sample itself, but the distinct occurrence of that sample's sequencing data based on its physical position in the sequencer component.

While a single biological sample may be sequenced multiple times across different physical components of the sequencer, a unique Product ID is generated by also considering a physical location. Even though the same sample is being sequenced, the different physical component (and possibly the tag index) results in a different alphanumeric identifier.

### Structure
A Product ID is generated from three core components:

* Run ID — Identifies the specific sequencing run in which the sample was processed. This represents a unique sequencing experiment or batch executed on the sequencer at a particular date/time (e.g., run date and instrument identifier)
* Sequencer Component — Identifies the physical component position on the sequencer where the sample was located during sequencing. It allows for multiplexing of multiple samples within a single run
* Tag/Barcode Index — Identifies the specific sample within the physical component using its index tag. This value distinguishes individual samples that were pooled and multiplexed together in the physical component

## Problem
The Mlwarehouse location table `seq_product_irods_locations` stores all the iRODS collections by linking them to their own Product ID. There is no constraint on the Product ID in the Mlwarehouse and the unique key is given by the couple Product ID and iRODS location. Moreover, the alphanumeric string has a very low probability to clash with a different run context.

## Solutions
### src/sangerdm/irods/retrieval.py::find_collections_by_id_products
The retrieval funtionality of iRODS collections is performed through Product ID metadata (`id_product`). The relationship in the DB cannot be constrained to `1 id_product -> 1 collection`, so the function can return all collections it finds or (by user choice) raise an exception in the case of multiple collections. In addition, whenever there is no collection in iRODS for a specific `id_product`, it can store an empty list or (by user choice) raise an exception.
